# Agent Debate Log: Authentic Shin-sal Engine Implementation

**Date**: 2026-02-12
**Topic**: Implementing Full 12 Shin-sal Calculation Logic

## 1. Context & Goal
- **Context**: Current ad-hoc implementation of Ghost Detector is insufficient and inaccurate.
- **Goal**: Implement a robust calculation engine for 12 authentic Shin-sal types based on classic texts.

## 2. Critique Points (Critic Agent)
- **Complexity**: Calculating 12 types for every user might impact performance if the logic is inefficient.
- **Data Integrity**: Are the formulas truly standardized? Conflicting sources could lead to user confusion.
- **UX Impact**: Showing too many types (12) might overwhelm users compared to the previous 3-5 types.
- **Regression**: Removing the current fallback logic might result in users seeing *no* ghosts if they don't match any specific criteria.

## 3. Defense & Refinement (Architect Agent)
- **Performance**: The calculations are simple lookups and string comparisons. O(1) complexity per user. Negligible impact.
- **Standardization**: Will use the most widely accepted formulas (Yeonhae-Japyeong).
- **UX Design**: We will only show detected ghosts, not all 12 slots.
- **Fallback Strategy**: We should keep the "Saju Structure Analysis" as a secondary layer if no specific Shin-sal is detected, ensuring every user gets *some* result.

## 4. Conclusion
- **Approved**: Proceed with implementation.
- **Action Item**: Add a "General Energy" fallback if 0 specific Shin-sals are found.
